# Model lighting, shadows, enemy lights and model reflections (static analysis, presentation round 3)

Everything here was read from the retail binaries (Lithtech.exe = E, server.dll = S, cshell.dll = C, object.lto = L); nothing was observed in a running retail game. Verdicts: **dead** = the shipped configuration/data never reaches the code, **unported** = live in retail, not in the remake.

## Enemy flashlight, M-14 laser ribbons, snow: probably dead in retail
* Snow (`snieg.spr`): C 0x100308fa / 0x10030a66 draw it only for a `d_emiter_opadu` with `Snieg 1`; the three worlds with that emitter (miasteczko0..2, one each) have `Snieg 0`: **dead**.
* Carried flashlight (Sig 551-p/SWAT, P90: items.txt `socket_niesiony_latarka latarka`) and the M-14 laser (`socket_niesiony_laser`): the per-frame weapon-instance pass C 0x1001d840 requires `[w+0x104] != 0` (0x1001d99c flashlight, 0x1002132e laser). The only stores to that byte in the whole DLL write zero (0x1004a124, 0x1004a3db when the NPC's `seen` flag +0x149 is set; 0x1004ad01 clear-all): nothing ever sets it, so the light, the glare, the beam and the ribbons are **dead** in retail (an original bug; static analysis only). The `enemy lights` option ([0x100b2499], default 1) gates the whole pass before that test.
* NPCs that would carry them (126 SIG, 21 M-14, 7 P90 over 23 levels) are listed in the coordinator report; the remake draws none, like retail.
* If it is ever wanted (exact, from an emulator run of the real code): light colour (0.6,0.8,0.8) radius 32 at the 800-unit trace end minus 16; two layers of 8 quads per weapon, near ring 0.48 at c = 0.48, far ring c = 168 s / 240 s with radii 19.2 s / 12 s (-R side 0.75 x), s = min(L/288, 1), additive (ONE/ONE), z-test no write, cull none, texture `latarka.dtx` x vertex colour (35,35,35,32) -> 0 and (15,15,15,12) -> 0; glare `latarkawrogow.spr` scale 1.5 w, colour sqrt(w), w = (1.2566371 - (a+b)) x 0.7957747 x (1024 - d) / 1024 with a, b the two view/beam angle ratios of 0x1001dd6f..0x1001e00c; laser: two crossed ribbons +-0.2 wide from the `laser` socket to 1.125 x the camera distance, colour (45,0,0,34), additive.

## Projected model shadows: off in the shipped configuration
* `textures\cien.dtx` (L 0x1000a044) belongs to the unplaced class `d_cien_chmur` (cloud shadow); `rs/cien.lta` is a per-model blend style the remake already picks by name.
* The model shadow is an engine render-to-texture system (E 0x508c80.., PS\BlurShadow.ps, 128 x 128 textures, MaxProjDist 200, radius x 1.1, alpha = object alpha x `ModelShadow_proj_alpha`). The switch `ModelShadow_Proj_Enable` (E 0x5a89ac) defaults to 0, autoexec.cfg ships `ModelShadow_proj_enable 0`, and only the options menu writes it (C 0x1002aa24, byte 0x100b23f8). A model also needs flag FLAG_SHADOW and the LTB property `ShadowEnable` (55 .ltb files). So a player who never touches the option never sees shadows; the remake keeps `options.model_shadow` stored and inert (**dead by default**).

## Model lighting (E 0x53f6c0..0x53fc99, 0x5382e0, 0x545280): unported
* Ambient: trilinear sample of the DAT light grid (header word 3 -> origin, cell size (always 250), dims, RLE RGB). Values are the floor 30 (20 in podziemia1a) inside levels and 0 in miasteczko0; cells inside solids are 255. The remake uses a flat 0.22.
* Static lights come from `Light` / `DirLight` / `ObjectLight` objects but only with `LightObjects != 0` AND `FastLightObjects == 0` (S 0x1003f7ed, 0x1003f86c): 1476 qualify, 669 `FastLightObjects 1` lights do not light models (the remake includes them).
* Coefficients `c_i = AttCoefs_i x Radius^AttExps_i` (default preset: (1, 0, 19/R^2)); modes from the `Attenuation` string: D3D `1/(c0 + c1 d + c2 d^2)`, linear `1 - d/R`, quartic `(1 - d^2/R^2)^2`; hard cut at R; dynamic OT_LIGHT objects use the D3D default. Up to 4 lights per model (cap 8) sorted by the max colour channel at the object; the rest (and ConvertToAmbient) fold into the ambient. D3D-mode lights become per-vertex point lights, the others one directional light per object.
* Not ported: the remake lights models with Bevy point lights (quartic falloff for every light, nearest 12 to the player, global ambient). A faithful port needs a per-object light set in a custom model shader; recorded, not done.

## Model reflections: retail ignores the DTX commands on models
* The DTX CommandString (`EnvMap`, `EnvMapAlpha`, `DetailTex`) is consumed only by `AllocShader` (E 0x4bf8b0, 0x4bf92c), i.e. world shaders; model pieces are drawn by E 0x542330 and bind textures only through RenderStyle passes (E 0x538940, BindTexture 0x5047d0 reads only the D3D texture). Only two model skins carry a command (`drzwi_winda.dtx` in rh12-lab2 and an orphan copy): the elevator door skin is drawn plain: **proved identical**.
* The reflections retail does draw on models come from RenderStyles: `lustro` (mirror, 6 props: burmistrz1/2, knajpa, lab1, wiez_wn2 x2) style 1 = `metal_z_maska`, `heli_lata`, the carried `fn_shotgun`, `zegar` glass (`szyby_z_metal`). `metal_z_maska`: stage 0 base x vertex colour, stage 1 `skins\bronie\odbicie.dtx` with BLENDCURRENTALPHA (rgb = odbicie x a + stage0 x (1 - a), a = the base skin's DTX alpha), texcoords = camera-space reflection vector (x, y), wrap. `automat_cola` (22 uses) is a self-illumination mask (base x a + base x vertex x (1 - a)). Unported (`models::style_alpha` ignores second stages).
